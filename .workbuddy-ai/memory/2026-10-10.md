## تشغيل التطبيق على محاكي أندرويد (Capacitor)

**الهدف:** تشغيل تطبيق Capacitor (Next.js web + Android shell) على محاكي الموبايل.

**البيئة:**
- Android SDK: `C:\Users\Ahmed\AppData\Local\Android\Sdk` (ANDROID_HOME / ANDROID_SDK_ROOT مضبوطان)
- JBR للبناء: `C:\Program Files\Android\Android Studio\jbr` (Java 21) — مضبوط في `android/gradle.properties` عبر `org.gradle.java.home`
- AVD المتوفر: `Medium_Phone_API_36.0` (data partition 6G، RAM 2048)
- المشروع: `D:\online-catalog-platform-5\android` — applicationId `com.nextcatalog.app`

**خطوات ناجحة:**
1. تشغيل المحاكي في الخلفية:
   `emulator -avd Medium_Phone_API_36.0 -no-snapshot-load -gpu swiftshader_indirect -no-boot-anim`
   والانتظار حتى `adb shell getprop sys.boot_completed` == 1
2. البناء: `cd android && ./gradlew assembleDebug` → الناتج `android/app/build/outputs/apk/debug/app-debug.apk` (~23.5MB)
3. التثبيت: `adb install -r <apk>` ثم `adb shell am start -n com.nextcatalog.app/.MainActivity`

**مشاكل واجهتنا وحلولها:**
- **فشل SSL عارض** عند تنزيل `kotlin-compiler-31.13.0.jar` من dl.google.com
  (`PKIX path building failed`) رغم أن curl و Java ينجحان بالاتصال. الحل: **إعادة تشغيل البناء** فقط — المهام الناجحة تُخزّن مؤقتاً فتكون إعادة المحاولة سريعة (~1 دقيقة).
- **`INSTALL_FAILED_INSUFFICIENT_STORAGE`**: قسم /data كان 95% ممتلئ. الحل: `adb shell pm trim-caches 999G` ثم إعادة التثبيت. (كذلك إزالة نسخة قديمة مثبتة 1.0.8 تساعد)
- ملاحظة: `MSYS_NO_PATHCONV=1` يكسر مسارات `adb install` — استخدم مسار ويندوز `D:/...` بدون هذا المتغير.

**ملاحظة معمارية:** `capacitor.config.ts` يضبط `server.url = https://tagr-online.com/home?native_android=1` — أي أن التطبيق يحمّل الموقع البعيد مباشرة داخل WebView، فالأصول المحلية في `out/` غير مستخدمة عند التشغيل الفعلي.
