## Per-merchant Meta Pixel (feature)

Built a merchant-facing tracking feature: each merchant can paste their own Meta Pixel ID and it runs on their storefront only.

### Files
- `supabase/migrations/0017_add_meta_pixel_id.sql` — `ALTER TABLE catalogs ADD COLUMN IF NOT EXISTS meta_pixel_id TEXT`. **NOT yet applied** (no Supabase access token / DB password in env; `supabase db push` not linked). User must run it in the Supabase SQL Editor.
- `src/lib/merchant-pixel.ts` — `META_PIXEL_RE` (`/^\d{15,16}$/`), `isValidMetaPixelId`, `trackPixel` (no-op safe), `pixelCurrency` (`+966`→SAR else EGP), `pixelValue`.
- `src/components/common/MerchantPixel.tsx` — client `next/script` init + PageView + noscript img; renders null on invalid ID; ID validated before injection (no raw user string).

Deliberately client-side: `headers()` in root layout would kill storefront ISR (`revalidate = 300`).
- `src/app/layout.tsx` — fb-pixel block removed, `<PlatformPixel />` rendered in body.
- `src/components/dashboard/SettingsForm.tsx` — new "التسويق والتتبّع" card (before the social-links card) with LTR numeric input + Events Manager link + active badge; zod `meta_pixel_id` refine; `watchedPixelId` via `useWatch`.
- `src/app/actions/catalog.ts` — `updateCatalog` parses `meta_pixel_id` only when the key is present in FormData (so auto-save callers never wipe it), validates, and has a retry-without-column fallback when migration 0017 is missing.
- `src/app/[slug]/ClientCatalogPage.tsx`, `src/app/[slug]/item/[itemId]/ClientProductPage.tsx` — render `MerchantPixel`; product page fires `ViewContent`.
