## مشكلة: الـ Service Worker بيفتح روابط متاجر تانية جوه التطبيق المثبّت

### الجذر (Root Cause)
- الـ `manifest` الخاص بكل متجر بيحدد `scope: /${slug}/` و `start_url: /${slug}` (دي الإعدادات الصحيحة).
- **لكن الـ Service Worker (`/sw.js`) مسجّل بـ default scope `"/"`** (في `ClientProviders.tsx` ما فيش `scope` option).
- الـ `fetch` handler في `sw.js` بيعمل **cache-first** لكل طلب GET — بما فيها صفحات `/[slug]` من متاجر تانية.
- نتيجة: لو متجر A مثبّت كـ PWA، والـ SW خزّن `GET /store-a`، فعندما المستخدم يفتح `GET /store-b` جوه التطبيق → الـ SW بيرجّع **cache غير صحيح أو blank** بدل ما يروح للسيرفر.

### الحل: تقييد الـ SW ليتعامل فقط مع الـ slug الحالي

#### 1. تعديل `public/sw.js` — إضافة فلتر في `fetch` handler
- نقرأ الـ `scope` المقصود من `clients.matchAll()` أو نخزّن الـ slug عند `install`.
- **الطريقة الأبسط:** نخزّن الـ `currentSlug` في `IndexedDB` أو `localStorage` عند `activate` (أو نمرّره عبر `postMessage` من الصفحة).
- في `fetch` handler:
  ```js
  // Only handle requests belonging to the current store's scope
  const url = new URL(event.request.url);
  if (url.origin === self.location.origin) {
    const pathSlug = url.pathname.split('/')[1];
    if (pathSlug && pathSlug !== currentSlug) {
      // Different store → let the browser fetch normally (no SW caching)
      return; // pass-through to network
    }
  }
  ```
- ده بيضمن إن الـ SW **مش** بيتدخل في روابط متاجر تانية.

#### 2. تعديل `src/components/common/ClientProviders.tsx` — تمرير الـ slug للـ SW
- نضيف `postMessage` بعد التسجيل عشان نبعت الـ slug الحالي للـ SW:
  ```js
  navigator.serviceWorker.register(versionedAsset('/sw.js')).then(reg => {
    reg.active && reg.active.postMessage({ type: 'SET_SLUG', slug: getCurrentSlug() });
  });
  ```
- ونضيف listener لـ `message` event في `sw.js` يحفظ `currentSlug`.

#### 3. تحديث `InstallPrompt.tsx` (اختياري)
- لو المستخدم فتح متجر تاني جوه التطبيق، الـ `manifest` scope بيطلع من الـ PWA أصلاً → المتصفح بيفتح الرابط في تبويب جديد. ده السلوك الصحيح المطلوب.

### الملفات اللي هتتعدّل
1. `public/sw.js` — إضافة `message` listener + فلتر `fetch` حسب الـ slug
2. `src/components/common/ClientProviders.tsx` — تمرير الـ slug عبر `postMessage`

### معايير النجاح
- متجر A مثبّت → فتح `/store-b` جوه التطبيق → يفتح المتجر B صح (مش A)
- الـ SW لسه بيشتغل للـ slug الحالي (caching/offline)
- مفيش أخطاء في الـ console

### مخاطر
- `postMessage` ممكن ما يوصلش لو الـ SW لسه مش `active` → نعالجها بـ `controllerchange` listener.
- لو الـ slug اتغير (تنقّل بين متاجر) → الـ SW لازم يحدّث `currentSlug` → نضيف `message` listener في الـ SW.
- iOS قد لا يدعم `postMessage` بنفس الطريقة → نعتمد على `scope` في الـ manifest كحماية أولية.
