# Custom Brand Theme Implementation Plan

> **For Claude:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** Add one safe custom storefront theme, where a merchant selects a light or dark background and a brand color while the app derives readable foreground, surface, and button colors automatically.

**Architecture:** Keep all ten existing `default` / `gradient-1` … `gradient-9` themes untouched. Add a `custom` theme identifier plus two small persisted values (`custom_theme_mode`, `custom_theme_color`), where the color is the chosen storefront background. A pure, dependency-free theme-token utility validates that the background matches its light/dark mode, computes WCAG contrast, and derives readable foreground, surface, border, and action colors; both storefront routes consume that one utility, so color decisions cannot drift between the catalog and product pages.

**Tech Stack:** Next.js 15, React 18, TypeScript, Tailwind CSS, Supabase/PostgreSQL, Zod, native CSS variables, Vitest (development-only unit tests).

---

## Locked product decisions

- The ten current themes retain their current IDs, gradients, card colors, and UI behaviour exactly as-is.
- `custom` is an eleventh option, available under the same Pro entitlement as the non-default themes.
- The merchant chooses a mode first (`light` or `dark`) and then one background/brand color. Each mode initially exposes a small recommended swatch palette; a native picker remains available for an exact brand color, but saving is rejected if that color is not light or dark enough for its selected mode.
- Text, icons, borders, cards, and button label colors are generated by code, not selected independently by the merchant.
- Accessibility target: WCAG 2.1 AA — contrast ratio at least 4.5:1 for normal text, 3:1 for large text and non-text UI boundaries. Primary-button label contrast is at least 4.5:1 and its fill contrasts with the background by at least 3:1.
- No runtime color library and no stored palette JSON. The browser receives a small style object only when `theme === 'custom'`.

**Step 3: Implement the minimal pure utility**

Implement only these exports in `src/lib/custom-theme.ts`:

```ts
export type CustomThemeMode = 'light' | 'dark';
export type CustomThemeInput = { mode: CustomThemeMode; color: string };
export type CustomThemeTokens = Record<
  '--store-background' | '--store-surface' | '--store-surface-strong' |
  '--store-foreground' | '--store-muted-foreground' | '--store-border' |
  '--store-brand' | '--store-brand-foreground' | '--store-ring',
  string
>;

export const isCustomThemeColor = (value: unknown): value is string =>
  typeof value === 'string' && /^#[0-9a-fA-F]{6}$/.test(value);

export function getAccessibleButtonForeground(hex: string): '#111827' | '#FFFFFF';
export function buildCustomThemeTokens(input: CustomThemeInput): CustomThemeTokens;
```

Use WCAG relative luminance (`sRGB → linear RGB`) and `(lighter + 0.05) / (darker + 0.05)` contrast calculation. A light choice must pass contrast against `#111827`; a dark choice must pass contrast against `#F9FAFB`. Use the validated selected color as `--store-background`; derive surface and border colors by blending it toward the matching neutral foreground, then derive `--store-brand` by moving its HSL lightness away from the page background until the action fill has 3:1 contrast. Return either dark or white button text only if it meets 4.5:1; otherwise throw a typed `InvalidCustomThemeColorError`. Never calculate colors from untrusted CSS strings.

**Step 3: Implement the narrow wrapper**

`StoreTheme` receives a catalog theme and custom fields. If it is not `custom`, it renders children without a style override. If it is custom, it applies `buildCustomThemeTokens` to a wrapper with `data-theme="custom"` and its own CSS variables. It must fail safely: missing/invalid stored fields render the default theme rather than injecting user-provided style.

In `globals.css`, add only scoped custom-theme selectors such as:

```css
[data-theme='custom'] {
  background: var(--store-background);
  color: var(--store-foreground);
}
[data-theme='custom'] .store-surface { background: var(--store-surface); border-color: var(--store-border); }
[data-theme='custom'] .store-primary { background: var(--store-brand); color: var(--store-brand-foreground); }
```

Do not change `.bg-gradient-default` or `.bg-gradient-1` through `.bg-gradient-9`.

**Step 4: Replace only duplicated branching for the custom case**

In both `StorefrontView.tsx` and `ClientProductPage.tsx`:

- Preserve their existing `getThemeClass` and `getCardColors` mappings for all pre-existing values.
